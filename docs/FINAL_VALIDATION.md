## Issues found during final validation (and resolutions)

1. **T08 rekey artifact (evidence, pre-existing).** Investigation showed T08's `rekey_observed` came from the feature extractor's passive heuristics (a bogus `0x0` ESP SPI from NAT-T IKE dissection plus a lifecycle regex matching the benign word "rekeying"), while runtime swanctl before/after show the identical child SA #177 with identical SPIs. Minimal Phase 5 evidence-parser correction applied: passive rekey claims now yield `possible_rekey` (warning), and runtime before/after SPI-set comparison is authoritative. Result: T08 correctly reports `no_rekey`; T14 (dedicated 60s rekey scenario) genuinely reports `rekey_observed` from a real SPI transition (child SA #201 `c238723c/c1395af4` -> #202 `c59309f6/c61e3f06`). Dataset, captures, feature extractor, and the ML model were NOT modified. Phase 5 (12 tests) and Phase 6 (3 tests) were re-run and pass; artifacts regenerated.
2. **Validator assumption corrected (final-validation only).** The first suite run failed its Phase 4 class-order check because a newer container numpy prints `model.classes_` in numpy-sorted order as `np.str_`. The delivered CLI already maps probabilities to schema classes **by label name**, so predictions were always correct; the validator now tests the actual property (schema-ordered probability keys, `PREDICT_OK True`). No model or pipeline change was made.
3. **Transient pip network timeout** during one demo container run was observed; the affected demo artifact was regenerated and the validation script now uses pip `--retries 5` with a retry loop for dashboard startup.
