# Dataset

## Final dataset: `dataset_v3_5_v2_full` (version `3.5-v2`)

This is the only dataset used by the delivered model and reports.

| Property | Value |
|---|---|
| Valid runs | 180 |
| Scenarios | 15 (T01-T15) |
| Traffic classes | 4 (`icmp`, `web`, `voip-like`, `video-like`) |
| Samples per class | 45 |
| Repetition per scenario/class | 3 |
| Duration range | 8-15 s (avg 11.56) |
| Empty PCAPs | 0 |
| Unique seeds | 177/180 (3 benign repeats, all distinct runs) |

## Corrected T15

The original T15 captured plaintext IPv6 alongside ESP (contamination). T15 was regenerated in an isolated environment:

- T15-only strongSwan configs (`testbed/config/t15-only/`) and compose override (`testbed/compose/t15.yml`).
- Clean-SA checks and IPv6 UDP/HTTP readiness preflights before every run.
- Transit-only capture filter (`tcpdump -i eth1 "esp or udp port 500 or udp port 4500"`).
- Runner validation: exactly two ESP SPIs, `no_rekey`, zero plaintext protected IPv6 packets.

All 12 final T15 runs pass with ESP-only transit captures. The historical v1 dataset (`dataset_v3_5_final`) is retained only as a previous experimental version and is **not** the final dataset.

## Per-run artifacts

```text
dataset_v3_5_v2_full/<scenario>/<run-id>/
    capture.pcap, metadata.json, features.json,
    swanctl-before.txt, swanctl-after.txt,
    xfrm-state.txt, xfrm-policy.txt,
    tcpdump-summary.txt, run.log, PASS.txt
```

`metadata.json` records ground truth (`vpn_ground_truth`, `traffic_ground_truth`), the scenario declaration, runtime observations, and `profile_version` (`3.5-v2` for T15, `3.5-v1` for T01-T14 captures generated by the same validated runner).

## Feature extraction

`analyzer/pcap_features.py` produces passive, encrypted-flow features: packet/byte counts, sizes, inter-arrival timing, burstiness, directionality, ESP/AH/IKE counts, and SPI counts. Raw SPI values are kept only as evidence, never as ML features.

## Grouped split metadata

`analyzer/build_ml_dataset.py` writes `dataset_exports_v2/traffic_features.csv` (180 rows) with features plus `group_*` columns (`group_scenario_id`, `group_run_id`, `group_seed`, `group_profile_version`, `group_duration`, `group_pcap_hash`). Group columns are used only for grouped splitting/auditing, never as model inputs.

## Excluded leakage fields

`scenario_id`, `traffic_class`, `traffic_type`, `family`, `run_id`, `folder`, `pcap`, `local_ts`, `remote_ts`, `ike_endpoints`, `scenario`, `traffic_ground_truth`, `vpn_ground_truth`, `run`, `metadata`, `raw_spi`, `esp_spis`, `ah_spis` are excluded from the ML feature vector (see `analyzer/LEAKAGE_AUDIT.md`).
